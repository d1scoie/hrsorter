## 1. გაზომვის მეთოდი
- ინსტრუმენტი: `python -m tools.evaluate`. ნაკრები → ცალკე დროებითი root → რეალური ნაკადი

  დამთხვევა), სრულად სწორი დოკუმენტების წილი, ავტომატიზაციის წილი, **ავტომატურებში** სწორი ტიპი და ზუსტი გვერდები,
  ველების სიზუსტე **და არასწორი მნიშვნელობის წილი** (გამოგონილი/არასწორი მნიშვნელობა ცალკე ითვლება, რადგან
  ის უფრო საშიშია, ვიდრე გამოტოვებული), გვერდების აღრიცხვა, დრო, პიკური მეხსიერება, ონლაინ გვერდები/ხარჯი.
- საცდელ რეჟიმში `proposed` ითვლება „ავტომატურად" (ესაა ის, რაც საცდელი რეჟიმის გამორთვისას `Sorted`-ში წავიდოდა).

  ერთი გენერატორიდანაა, ამიტომ ისინი ერთმანეთისგან სრულად დამოუკიდებელი არ არის.

| ადგილობრივი: ტექსტური ფენა + Tesseract (`kat+eng`) | ადაპტერი, ხარისხის შემოწმება, მობრუნება/დახრა, OSD | ტექსტური ფენა — კი (სინთეზური); **Tesseract — არა** (არ არის დაყენებული) |
| ონლაინ: Claude ვიზუალური მოდელი (`claude-opus-5-5`, Anthropic API) | ადაპტერი, ორმაგი ჩართვა, გასაღები Credential Manager-ში, timeout, retry, დღიური ლიმიტი, ტოკენების/ხარჯის აღრიცხვა | **არა** — გასაღები და დოკუმენტების გარეთ გაგზავნის თანხმობა არ არის |
| შერეული (`hybrid`): ადგილობრივი, ონლაინ მხოლოდ დაბალი ხარისხის გვერდებზე | მზადაა | არა |

შედარების გასაშვებად, ერთსა და იმავე მონიშნულ ნაკრებზე:
```powershell
.venv\Scripts\python.exe -m tools.evaluate --gt real\ground_truth.json --work D:\eval\w1 --ocr-path local  --label "ადგილობრივი" --out D:\eval\local.json
.venv\Scripts\python.exe -m tools.evaluate --gt real\ground_truth.json --work D:\eval\w2 --ocr-path online --label "ონლაინ"      --config config\config.json --out D:\eval\online.json
.venv\Scripts\python.exe -m tools.evaluate --gt real\ground_truth.json --work D:\eval\w3 --ocr-path hybrid --label "შერეული"     --config config\config.json --out D:\eval\hybrid.json
```
ონლაინ/შერეული გზისთვის საჭიროა `ocr.online.enabled=true`, `provider="anthropic"` და გასაღები
(`hrsorter secret set hrsorter/online_ocr`). ანგარიში აჩვენებს ტოკენებს და სავარაუდო ხარჯს გვერდზე.
ფასი config-ით იცვლება; ნაგულისხმევია $4 / $20 1M input/output ტოკენზე (claude-opus-5-5, 2026-10).

**წინასწარ არ ვამტკიცებთ** Tesseract-ის ან ონლაინ მოდელის საკმარის სიზუსტეს ქართულ ხელნაწერზე. ხელნაწერი ველები
(განსაკუთრებით პირადი ნომერი) ახლა სანდოდ არ ითვლება: ფაილის სახელში არ ხვდება და გადამოწმების ნიშანი ედება.
ხელმოწერის ცალკე დეტექტორი ჯერ არ გამოგვიყენებია: მუშაობს მარტივი ევრისტიკა (მელნის ლაქები ხელმოწერის ხაზთან).
მისი საჭიროება რეალურ ნიმუშებზე უნდა შეფასდეს. ხელმოწერის სტატუსი გადარჩევას არ აფერხებს.

## 6. რა არის საჭირო საბოლოო შეფასებისთვის (ეტაპი 5)
1. **რეალური ნიმუშები:** მინიმუმ 200 დოკუმენტი, ხშირ ტიპზე მინიმუმ 20. შემადგენლობა: სხვადასხვა შაბლონი,
   ცუდი/მობრუნებული სკანები, ხელნაწერი ველები, ხელმოწერა/ბეჭედი ცალკე გვერდზე.
2. **მონიშვნა:** `ground_truth.json` (ფორმატი `tools/evaluate.py`-ში). ორ ნაწილად გაყოფა: კალიბრაციისა და
   საბოლოო შეფასების. ერთი დოკუმენტის ხელახალი სკანები ორივე ნაწილში არ უნდა მოხვდეს.
3. Tesseract-ის დაყენება `kat` ენით და ადგილობრივი გაზომვა. ონლაინ შედარება მხოლოდ შენი თანხმობით.
4. ზღვრების (`thresholds.*`) დაკალიბრება კალიბრაციის ნაწილზე. შემდეგ ერთჯერადი გაზომვა შეფასების ნაწილზე.
5. ტიპების ჩართვა `auto_save_enabled`-ზე სათითაოდ, მხოლოდ იმ ტიპების, რომლებიც ≥99%-ს აკმაყოფილებს.
   საცდელი რეჟიმის გამორთვა.
6. თანამშრომლების API-ის რეალური აღწერა (მისამართები, ავტორიზაცია, ველები). ამის შემდეგ `employee_api.mode="http"`.
